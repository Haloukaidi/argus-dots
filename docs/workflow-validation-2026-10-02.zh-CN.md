日期：2026-10-02。原始基准：`9cfe9129fd90511c3a1865844ec7dfda1b5d1008`。

本轮在既有 dots 适配器基础上，检查真实 Argus 调度、审阅、持久化、Git 和文件系统边界。没有用户原报错的截图或日志，因此下面是本轮独立复现的问题，不能认定它们就是用户此前遇到的同一个案例。

## 已复现并修复的问题

### Review 停止信号

原版 research Reviewer 的三个并行 specialist 没有继承请求级 ContextVar。已请求停止时仍能启动三个后端调用，运行中的调用也得不到原来的中断 callback。现在每次提交分别复制上下文，继续使用既有中断机制。并行角色之间的上下文和 dots 工具绑定不串线。

### 工具繁忙时的取消通道

原版全部八个 handler 可被六个活动操作和两个尚未完成清理的繁忙响应占住，取消请求在识别操作之前就被拒绝。现在保留七个普通 handler 和一个经过认证的控制 handler，业务操作仍最多六个、总 handler 仍最多八个。

只有普通槽满时才进行最多 50 ms 的只读请求头探测；指定取消路径、正确 token、单一有效 Content-Length 和无分块传输都要满足，之后仍由原 Handler 完整验证请求。没有增加端口、环境变量、JS 协议或无界队列。取消 callback 留在后台线程，关停不等待阻塞的 callback。

边界仍然存在：过载时未到齐的请求头可以返回 busy；合法控制请求若不发送完整 body，会占用控制槽直到原有约三秒读超时；已经认证的慢取消操作也可能占用唯一控制槽。不能据此宣称抵御无限恶意流量。

### Git 诊断与项目身份

- 缺失或不可执行 Git 不再直接抛出未处理的启动异常，checkpoint 返回明确错误
- Git dubious ownership、损坏引用、锁和权限错误不再被静默当成没有变化；真正非仓库、空分支和无变化仍保持原有 no-op
- HEAD 不存在且没有诊断时，再以只读 symbolic-ref 确认空分支，不修改分支或真实 index
- 读取 remote 之前先确认处在 worktree，避免全局 remote.origin.url 让两个普通目录共享同一项目身份
- 仅 checkpoint 的子进程环境固定 Git 诊断语言；不修改用户全局环境或 safe.directory

### 路径字符与恢复身份

原版的 strip 和文本换行转换会损坏合法目录名。存在相邻的 `repo` 与末尾含空格或回车的仓库时，checkpoint 可能写进错误的邻仓库。现在从原始 Git 字节读取路径，只去掉 Git 自己输出的一个终止换行，再做保真解码；持久化 workdir/base_workdir 仅判空时裁剪空白，恢复时使用原字符串。

已验证普通 Unicode、尾空格、tab、LF、CR、CRLF、双 LF、内部换行，以及 POSIX 非 UTF-8 字节目录。非 UTF-8 路径在 JSON 中使用可还原转义，正常 Unicode 保持可读。回归检查采用、重开和 checkpoint 都指向原仓库，邻仓库的 refs、HEAD、真实 index 和文件不被修改。

### Campaign 状态写入与损坏状态

两个并发采用操作原来共用一个临时文件，可能在 replace 时报文件不存在。现在各操作使用同目录独立临时位置后再原子替换，保留已有文件创建权限和持久化语义。注入写失败或 replace 失败时，旧记录和权限保留，临时内容清理。

持久化路径包含 NUL 或目标后来成为软链环时，恢复返回不可用，不再由对应 Path.resolve 异常直接崩溃；没有自动删除或改写损坏记录。

### Dots 默认模型与学习调用

这是 dots 新增集成缺口：真实任务完成后的 reflection 和 Curator 调用，会把 `dots` 送进仅支持 CLI 的模型解析器而失败；框架的空字符串模型默认值也被传输层拒绝。

现在仅在模型解析处把显式 dots 视为无固定模型目录的非 CLI 后端，保留显式模型优先级、未知后端拒绝和既有 CLI 语义。只有模型空字符串规范为 null，其他非法类型和空白仍在提交前拒绝。effort、执行能力门禁和 native 权限没有扩大。

## 实际贯穿的任务链

受控后端经过原 `build_dots_life_runner`、Planner、LifeSupervisor 和 SkillLoop，完成以下工程任务：

1. 在隔离项目中生成一个小函数及两项真实 unittest
2. 第一轮真实测试出现空输入错误
3. 原 Reviewer action dispatcher 发出 revise，下一轮 Engineer 收到原反馈
4. 修复临时项目后，两项真实测试通过，Reviewer 发出 approve
5. 按原有规则由 Manager 关闭普通任务阶段，或保留 Planner 中间任务的阶段权限边界
6. reflection 成功记录一次性完成凭据，重开持久状态后不重复执行已完成任务

普通路径、空格加中文路径和超过 260 字符的 Linux 深路径均覆盖。另单独通过真实 Curator callback 检查默认模型和角色路由。它们验证的是原代码加受控后端的功能链；没有把它们称为全五角色 native/provider 生产运行。

## 仍受测试环境限制的检查

本环境缺少 PR-gate 所需的 `/proc/self/task/<pid>/children`，AF_UNIX socket 创建也返回 EPERM。两项代表检查在经过受支持的单次执行审批后仍失败。没有以假进程枚举、取消清理或修改系统安全设置把这些检查做成通过。

两个原测试还依赖不稳定前提：Manager 的既有异步 answer-learning 可增加一次调用，而测试只允许两次；该项本次完整运行通过，但此前隔离诊断已确认时序假设。“缺 Python”测试在源码树已有 `.venv` 时并未真的移除全部解释器，是全库结果中保留的一个 fixture 失败。全库结束后，在不含 venv 的干净完整源码树中使用外部测试解释器复跑该原测试，1 项通过，耗时 0.10 秒；没有修改原测试或断言。这个独立结果验证了前提差异，不替换此前完整运行的原始统计。
