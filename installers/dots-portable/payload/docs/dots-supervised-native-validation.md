# Supervised native validation, 2026-10-03

This record covers the explicit `dots` execution profile
`supervised-approx-v1` and protocol 4. Production source was frozen at
`3bb96e2ab95493bdcb9b34ee873bb60bc936a45e` during these trials. The strict
`dots` path remains fail-closed and has no provider-CLI fallback.

Earlier protocol-1/2/3 observations in [native validation](dots-native-validation.md)

## Normal Web API acceptance

A live native coordinator owned actual native worker spawning, binding, typed
replies, terminal observations and interruption. The producer used the supported
`argus.apps.dots_web` launcher and original `POST /api/daemons` entry; the original
detached daemon retained the same immutable host binding. Neither the parent
nor a substitute scheduler inserted the role sequence.

The fixture was a small software repair: empty-input arithmetic mean returns
float `0.0`, three original tests are preserved, a fractional test is added,
and a README gives the test command. The normal Manager selected existing
software, staged workflow and independent review. The original Planner created
one bounded mission, Engineer implemented it, and independent Reviewer checked
candidate source, original tests, behavior, compilation and test results.

Acceptance observed all of the following:

- A real native Reviewer invoked original `approve_review`; its saved reply
  recorded that action, with no pending/inflight tools before terminal recording
- The Reviewer request reached completed and consumed status. The terminal
  integrity check accepted unchanged candidate/evidence before gateway success
- Original `round.review.completed` reported `done`, followed by bounded
  `life.mission.completed` with `success=true` and `status=done`
- Independent post-stop verification passed all four tests, in-memory compilation
  and public behavioral probes; all three original method source segments
  matched the protected pre-edit snapshots exactly, with one added test
- Both baseline files and their manifest still matched independently saved
  pre-admission hashes. No bytecode cache was created
- Eight requests settled: five completed and three cancelled. No native worker
  turn or typed tool remained active. The producer was sealed and host stopped
- The original daemon stop returned success without force; the owned local Web
  service exited after its normal termination signal

The fixed scope was 24 calls, one active worker and a 30-minute session. Original
per-call timeouts and the session expiry were not extended. The native host
renewed the lease itself; no unattended renewal timer impersonated a coordinator.
The target renewal cadence was under 20 seconds, but tool/transcription latency
caused longer gaps, up to 53.389 seconds, still below the 60-second lease. This
leaves limited operational headroom and is not a guarantee of unattended uptime.

   and the mission failed. A narrow audited repair registers only the original

2. A staged trial reached native Reviewer and a real typed evidence question.
   It had preserved initial test-run output but no pre-edit source snapshot,
   so unchanged-test provenance could not be established. The original
   300-second Reviewer timeout fired; no approval was fabricated or inferred

native admission. The normal task objective supplied those baseline paths. The
existing `ARGUS_SKILL_REVIEWER_READ_DIRS` host knob included only the exact baseline
directory, so original Reviewer options and the guard covered it. Profile
`read_roots` alone authorizes a location; it does not automatically snapshot it.
A deterministic original-Reviewer check accepted unchanged evidence and blocked
a copied baseline mutation even after typed approval. No permission change or
weakened verdict rule was used to obtain the later pass.

## Separate protocol-4 continuation and Curator probes

These targeted original-function probes are separate from the normal Web
acceptance above and from older protocol-2 continuation evidence. The fixture
explicitly selects Planner rolling sessions; ordinary dots `auto` remains fresh.

The first targeted attempt stopped after one genuine completed Planner call.
Its exact-tree postcheck detected four lazily initialized original host metadata
files: backlog commit/lock and operator-context projection/lock. Existing fixture
bytes were unchanged, but no resume or Curator call was admitted. That attempt
remains a failed fixture check, with its producer sealed and host drained.

A fresh corrected fixture performs the exact original context reads before
capturing its full integrity baseline, renders original full/resumed prompts,
and constructs the inert original Curator without invoking its callback. Repeating
these operations leaves all files unchanged. The four metadata files are retained
in the protected baseline; no broad ignore or source patch is involved.

The corrected fresh scope completed exactly three native requests with one
active role and a 20-minute session:

- Original `Planner.plan_next` ran twice with the same objective. The original
  capsule emitted `fresh`, then `resumed`, and retained two turns
- The coordinator invoked the real native followup tool on the first worker.
  The second request's actual accepted worker was identical, its nullable
  mission identity and resolved model/effort were unchanged, and its current
  terminal marker was observed. The second prompt used original delta context
- Original `LifeWorker._build_curator` / `_curator_distill_fn` reached
  `Curator._distill_root`. The leaderboard was folded from actual tiny fixture
  test outcomes, including an explicitly failed empty-input check, not an

- Independent checks matched the strategy to the exact consumed Curator reply,
  preserved all fixture and measured-input hashes, and found only the intended

  the producer sealed, host stopped, and no native turn/tool remained active

This establishes protocol-4 continuation through an original Planner capsule
and one original Curator distillation path. It does not validate the Curator's

verdicts represented concrete pending work, not validated implementation
instructions: one proposed test-discovery command could omit the existing test
layout. The probe did not execute that plan or certify strategy correctness,
and no additional native call was used to conceal this content limitation.

## What this establishes, and what it does not

This is one bounded real Manager → Planner → Engineer → Reviewer software
mission through the normal Web API and detached daemon. Browser graphical
navigation to the local service was blocked in the test environment; it is not
reported as a browser-UI pass. No research mission or production deployment ran.

The original short Manager supervision timeout occurred during the trial.
Actual cancellation/interruption was reconciled; a cancelled or late native
answer was not published as successful supervision. Concurrent host/state writes
inside a protected review snapshot can still conservatively reject multi-round
work. This limitation has no broad telemetry exclusion.

Native observed model, token counts and billing remain unavailable. The exact
profile explicitly mapped requested low/high/default effort to native `xhigh`;
requested values were retained separately. There was no model substitution.
The real supervisor reported cost `null` with empty accounting, not measured zero
cost. No per-call token or cost estimate was invented.

Native OS isolation, working directories and disabled-tool requests remain
advisory. The guard provides trusted-host change detection, not filesystem
prevention or authentication against a malicious process sharing the OS user.
A fresh lease asserts recent host participation, not proof of a running worker.

The candidate runtime reported its exact source revision. Its inherited release
manifest had not been regenerated during the trial; this record does not claim
an updated packaged release, publication or deployment.
